# 리블 — 한국 아파트 데이터 조회

전국 아파트 약 45,000개의 공공데이터 기반 지표를 `reevl` MCP로 조회한다.

## 순서

1. **`describe_fields`를 먼저 부른다.** 축 이름과 **단위**, 값 분포를 준다.
   단위를 모르고 범위를 넣으면 조건이 100배 틀린다.
2. `search_apartments`로 후보를 좁힌다.
3. 특정 단지를 판단해야 하면 그 `cid`로 `get_apartment`.
4. 시장·정책 맥락이 필요하면 `list_articles`.

## 함정 — 실제로 틀린 답이 나갔던 것들

### `region`이라는 축은 없다

지역은 **`sido` · `gu` · `dong`**으로 나눠 넣는다.

```
✗ {"region": "서울 강남구"}
✓ {"sido": "서울", "gu": "강남구"}
```

값은 **완전일치**다. `gu: "강남"`은 0건이고 `gu: "강남구"`가 718건이다.
0건이 나오면 철자를 의심하고 `describe_fields({field:"gu", sido:"서울"})`로 실제 값을 확인한다.

### 가격 단위는 **만원**이다

```
15억 → price_max: 150000     (150000000이 아니다)
```

### `광주`의 시도 값은 **`전남광주`**다

2026년 7월 1일 **전남광주통합특별시**가 출범해 광주광역시와 전라남도가 하나가 됐다.
데이터 오류가 아니라 현재의 행정구역이다.

`sido: "광주"`는 자동으로 `전남광주`로 고쳐지고, 응답의 `normalized`에 그 사실이
적혀 온다. 다만 범위가 넓어 **목포시·순천시까지 함께** 나온다.
옛 광주 도심만 필요하면 `gu`로 좁힌다 — 그 안에서 `구`로 끝나는 곳이다
(광산구·북구·서구·남구·동구).

### `status` — 분양 예정 단지를 구분한다

응답의 모든 단지에 `status`가 붙는다.

| 값 | 뜻 |
|---|---|
| `existing` | 기존 단지. 실거래 이력이 있다 |
| `upcoming` | **분양 예정.** `price`가 시세가 아니라 **분양가**이고 거래·공시 이력이 없다 |
| `unranked` | 무순위 청약 |

예측 축(`fc*`)으로 정렬하거나 범위를 걸면 **`existing`만 남는다.** 예정단지는
실거래가 없어 콜드스타트 예측이 나오고, 그 값이 실단지보다 세 배 커서 순위를
통째로 점령하기 때문이다(실측: 예정 최대 +68% vs 실단지 +21%).

지역·가격으로 찾을 때는 예정단지도 그대로 나온다 — 가리는 게 아니라
**같은 줄에 세우지 않을 뿐이다.** 예정단지만 보려면 `status: "upcoming"`.

★`upcoming` 단지를 답에 옮길 때는 **아직 지어지지 않았고 가격이 분양가라는 것**을
반드시 함께 말한다.

## 답할 때

- **출처와 갱신일을 붙인다.** 응답의 `source`·`units`에 들어 있다.
- 숫자를 옮길 때 단위를 바꾸지 않는다(만원 → 억은 계산해서 쓰되 원 단위로 오해하지 않게).
- **투자 자문이 아니다.** 참고용 통계이고 거래 판단의 책임은 사용자에게 있다는
  고지가 응답의 `notice`에 있다. 매수·매도를 권하는 문장으로 답하지 않는다.
- 조건에 맞는 단지가 없으면 **없다고 말한다.** 조건을 임의로 완화해서 채우지 않는다.

## 도구

| 도구 | 쓰임 |
|---|---|
| `describe_fields` | 축·단위·값 분포. **조건 검색 전에 부른다** |
| `search_apartments` | 조건 검색. `sido`/`gu`/`dong`/`brand`/`builder`/`q` + `<축>_min`·`_max` |
| `get_apartment` | `cid` 하나의 전 축 상세 |
| `list_articles` | 리블이 발행한 부동산 브리핑(정책·시장) |
